# ADR 005: 원본 보존과 일별 상품 수요 모델의 경계

## 상태

채택

## 배경

`raw.retail_sales`에는 정상 판매뿐 아니라 취소, 반품, 무료 제공, 음수 가격,
고객 ID가 없는 주문도 함께 저장되어 있습니다. 이 기록들은 원본에서 삭제할 오류가
아니라, 어떤 기준으로 분석했는지 설명하기 위해 보존해야 하는 비즈니스 사건입니다.

반면 향후 수요 예측에는 날짜와 상품별로 실제 판매된 수량을 일관된 기준으로 계산한
테이블이 필요합니다. 원본 테이블에서 바로 분석하면 사람마다 취소와 반품을 다르게
제외해 같은 질문에도 다른 결과를 만들 수 있습니다.

## 결정

dbt는 기존 `raw.retail_sales`를 수정하지 않고 읽기 전용 source로 사용합니다. 모델은
다음 세 경계로 시작합니다.

| 계층 | 첫 모델 | 한 행의 의미 |
|---|---|---|
| source | `raw.retail_sales` | 원본 CSV의 판매 기록 한 행 |
| staging | `stg_retail_sales` | 타입과 품질 플래그를 유지한 정리된 판매 기록 한 행 |
| mart | `mart_daily_product_demand` | 판매 날짜와 상품 코드 조합 한 건 |

첫 mart는 국가나 고객 ID를 행 구분 기준으로 사용하지 않습니다. 고객 ID가 없는
주문도 상품 수요에는 실제 판매 신호가 될 수 있으므로 집계에 포함합니다.

수량은 하나의 숫자로 덮어쓰지 않고 다음 의미를 분리합니다.

- `sold_quantity`: 수량이 양수이고 취소가 아닌 행의 수량 합계
- `returned_quantity`: 수량이 음수인 행의 절댓값 합계
- `net_quantity`: 원본 `quantity`의 합계
- `sales_line_count`: 집계에 포함된 원본 행 수
- `anonymous_line_count`: 고객 ID가 없는 원본 행 수
- `cancellation_line_count`: 취소 송장으로 표시된 원본 행 수
- `return_line_count`: 수량이 음수인 원본 행 수

매출 지표는 `quantity * unit_price`를 기반으로 하되, 음수 가격과 무료 제공 행을
숨기지 않고 별도 개수로 노출합니다. 정확한 컬럼 이름과 SQL은 작은 모델별 테스트를
작성하면서 확정합니다.

## 품질 원칙

- staging에서는 취소·반품·익명 주문을 삭제하지 않습니다.
- source 행의 식별자인 `source_file_sha256`, `source_row_number`를 유지합니다.
- `stg_retail_sales`는 source와 같은 행 수와 같은 유일키를 가져야 합니다.
- mart의 유일키는 `sale_date`, `stock_code` 조합입니다.
- 수요 계산 규칙은 SQL 조건과 dbt 테스트로 함께 검증합니다.
- dbt 결과는 `analytics` 스키마에 만들고 `raw`, `ops`는 수정하지 않습니다.

## 결과

원본 데이터의 흔적을 잃지 않으면서, 취소와 반품을 어떻게 계산했는지 설명 가능한
일별 상품 수요 테이블을 만들 수 있습니다. 대신 수요 정의가 바뀌면 mart의 지표와
테스트를 함께 변경해야 하며, 고객·국가 분석은 별도 모델로 확장해야 합니다.
